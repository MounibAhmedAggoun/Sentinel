# HTTP-002: Security header not observed: Strict-Transport-Security

- **Area:** http
- **Severity:** low

## What is observed

No Strict-Transport-Security header was seen in an HTTPS response.

## Why it can matter

Strict-Transport-Security tells a browser to use HTTPS only for a site, for a set time. Without it, a request that starts as http:// goes over plain HTTP before any redirect, which leaves a window in which someone on the network path could interfere.

## False positives

The header only means something on HTTPS, so Sentinel does not judge plain HTTP responses. Browsers remember the header for the whole max-age, so it should be enabled only when every page works over HTTPS. Adding includeSubDomains extends that to all subdomains, and it should be added only when they all use HTTPS too.

## How to fix

### nginx

```
add_header Strict-Transport-Security "max-age=31536000" always;
```

### Apache

```
# Needs mod_headers.
Header always set Strict-Transport-Security "max-age=31536000"
```

### Caddy

```
header Strict-Transport-Security "max-age=31536000"
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000');
  next();
});
```
