# COOKIE-005: Cookie observed with a __Secure- prefix but without Secure

- **Area:** cookie
- **Severity:** low

## What is observed

A cookie named with the __Secure- prefix has no Secure flag.

## Why it can matter

A cookie whose name starts with __Secure- asks the browser to accept it only if it also has the Secure flag and was set over HTTPS. Browsers that support prefixes reject a __Secure- cookie without Secure, so the cookie may never be stored and the feature that relies on it may silently not work.

## False positives

Sentinel judges this only for cookies set on HTTPS responses, and it sees only cookies set on anonymous requests. Names are matched case-sensitively, as browsers do, and only at the start of the name. A cookie that merely contains the text elsewhere in its name is not judged. Very old browsers ignore prefixes and may still store the cookie.

## How to fix

### Express

```
res.cookie('__Secure-sid', value, { secure: true });
// Behind a proxy, also set app.set('trust proxy', 1).
```

### Apache

```
# Needs mod_headers. Appends the flag to every cookie, so it can
# duplicate a flag the application already sets.
Header always edit Set-Cookie ^(.*)$ $1;Secure
```
