# TLS-006: Outdated TLS protocol version accepted

- **Area:** tls
- **Severity:** medium

## What is observed

The server accepted a handshake pinned to TLS 1.0 or TLS 1.1. Checked only with --probe-legacy-tls.

## Why it can matter

TLS 1.0 and TLS 1.1 are old protocol versions with known weaknesses. The IETF formally deprecated them, and current browsers no longer use them. A server that still accepts them lets a client that supports nothing newer connect with weaker protection.

## False positives

This is checked only when Sentinel runs with --probe-legacy-tls. Sentinel tries a handshake pinned to each old version, and OpenSSL 3 may refuse old versions at its default security level, so the probe uses a lower level for those attempts only. An accepted handshake shows that the server allows the version, nothing more. A device that needs to serve old clients can accept it on purpose.

## How to fix

### nginx

```
ssl_protocols TLSv1.2 TLSv1.3;
```

### Apache

```
SSLProtocol -all +TLSv1.2 +TLSv1.3
```

### Caddy

```
# Caddy already allows TLS 1.2 and 1.3 only by default.
# To state it explicitly:
example.com {
    tls {
        protocols tls1.2 tls1.3
    }
}
```
