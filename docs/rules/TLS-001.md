# TLS-001: Certificate expiry date has passed

- **Area:** tls
- **Severity:** high

## What is observed

The certificate expiry date is in the past.

## Why it can matter

A certificate has an expiry date. After it passes, browsers show a full-page warning and many clients refuse to connect, so visitors cannot use the site normally.

## False positives

Sentinel compares the certificate date with the clock of the machine running the scan, so a wrong system clock can cause a false match. The server may also serve different certificates depending on the name or the IP address that was requested. Sentinel reads the certificate from one connection.

## How to fix

### nginx

```
# With certbot, renew and reload:
sudo certbot renew
sudo systemctl reload nginx
# Check that automatic renewal works:
sudo certbot renew --dry-run
```

### Apache

```
sudo certbot renew
sudo systemctl reload apache2
# Check that automatic renewal works:
sudo certbot renew --dry-run
```

### Caddy

```
# Caddy obtains and renews certificates automatically for sites with a hostname.
# If a certificate expired, check the logs for the reason renewal failed:
journalctl -u caddy --no-pager | tail -n 50
```
