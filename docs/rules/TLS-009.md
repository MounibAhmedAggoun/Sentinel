# TLS-009: Certificate observed with a weak signature algorithm

- **Area:** tls
- **Severity:** medium

## What is observed

The certificate is signed with SHA-1 or MD5.

## Why it can matter

A certificate signature proves that a certificate authority issued the certificate. SHA-1 and MD5 are hash functions with known weaknesses, so a signature made with them is easier to forge than one made with SHA-256 or stronger. Browsers no longer trust certificates signed with SHA-1 or MD5.

## False positives

Sentinel reads the signature of the certificate the server presented first, the leaf, and not the certificates further up the chain. It matches the words SHA-1 and MD5 in the algorithm name that Node reports. A certificate from a private authority on an internal system can still use an old algorithm on purpose.

## How to fix

### nginx

```
# Replace the certificate with one signed with SHA-256 or stronger.
sudo certbot --nginx -d example.com
```

### Apache

```
sudo certbot --apache -d example.com
```
