# COOKIE-001: Cookie flag not observed: Secure

- **Area:** cookie
- **Severity:** low

## What is observed

A cookie set over HTTPS has no Secure flag.

## Why it can matter

The Secure flag tells a browser to send a cookie only over HTTPS. A cookie set over HTTPS without it may also be sent over an unencrypted http:// connection, where someone on the network path could read it. This matters most for session cookies.

## False positives

Sentinel makes anonymous requests, so it only sees cookies the site sets before any login. It checks cookies set on HTTPS responses and keeps the first one seen for each name. A cookie that carries no sensitive value, such as a language preference, can match without being a problem.

## How to fix

### nginx

```
# For proxied applications. Needs nginx 1.19.3 or newer.
proxy_cookie_flags ~ secure;
```

### Apache

```
# Needs mod_headers. Appends the flag to every cookie, so it can
# duplicate a flag the application already sets.
Header always edit Set-Cookie ^(.*)$ $1;Secure
```

### Express

```
res.cookie('sid', value, { secure: true });
// Behind a proxy, also set app.set('trust proxy', 1).
```
