# COOKIE-003: Cookie flag not observed: SameSite

- **Area:** cookie
- **Severity:** low

## What is observed

A cookie has no SameSite attribute.

## Why it can matter

The SameSite attribute tells a browser whether to send a cookie with requests that start on other sites. Setting it to Lax or Strict limits that, which reduces some cross-site request forgery risks. Without the attribute, the browser applies its own default.

## False positives

Current browsers treat a cookie without SameSite as Lax, so the real difference is smaller than it once was. Older browsers may behave differently. Setting the attribute mostly makes the behaviour explicit. A cookie that must be sent cross-site, such as one used in an embedded widget, needs SameSite=None with Secure.

## How to fix

### nginx

```
# For proxied applications. Needs nginx 1.19.3 or newer.
proxy_cookie_flags ~ samesite=lax;
```

### Apache

```
# Needs mod_headers. Appends the attribute to every cookie, so it can
# duplicate one the application already sets.
Header always edit Set-Cookie ^(.*)$ $1;SameSite=Lax
```

### Express

```
res.cookie('sid', value, { sameSite: 'lax' });
```
