# TCP-001: TCP port &lt;port&gt; observed open

- **Area:** tcp
- **Severity:** informational

## What is observed

A port on the allowlist accepted a TCP connection.

## Why it can matter

An open port means a service accepted a TCP connection from the scanning host. An open port is not a weakness by itself. Whether it matters depends on which service is behind it and who is meant to reach it, so this is an inventory note: it shows what can be reached from where the scan ran.

## False positives

Ports 80 and 443 are normal for a web server, and the finding says so. Sentinel only tries a short allowlist of ports, from one machine, so a port that looks open may be closed to other networks, and a port that looks closed may be open to them. A firewall or load balancer in front of the host can also answer for ports that nothing listens on.

## How to fix

### ufw (Linux firewall)

```
# Allow only what should be public, then deny the rest.
sudo ufw default deny incoming
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

### iptables

```
# Drop inbound traffic to a port that should not be public.
sudo iptables -A INPUT -p tcp --dport 8080 -j DROP
```

### Docker

```
# Bind a published port to localhost only, instead of all interfaces.
docker run -p 127.0.0.1:8080:8080 your-image
```
