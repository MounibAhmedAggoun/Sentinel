# TLS-010: HTTP/2 not observed as offered

- **Area:** tls
- **Severity:** informational

## What is observed

The server did not choose HTTP/2 when it was offered during the TLS handshake.

## Why it can matter

During the TLS handshake a client lists the application protocols it speaks, and the server picks one. HTTP/2 sends many requests over one connection, which can make pages load faster than HTTP/1.1. When the server picks something else, or nothing, it does not offer HTTP/2 to this client.

## False positives

HTTP/1.1 is fully supported and is not a weakness, which is why this is informational. A server may offer HTTP/3 through another route that Sentinel does not look at. Some proxies and load balancers pick the protocol per connection. Sentinel offers h2 and http/1.1, sends no request, and reads the choice from one handshake.

## How to fix

### nginx

```
server {
    listen 443 ssl;
    http2 on;   # nginx 1.25.1 or newer. On older versions use: listen 443 ssl http2;
}
```

### Apache

```
# Needs mod_http2.
Protocols h2 http/1.1
```

### Caddy

```
# Caddy enables HTTP/2 by default for HTTPS sites.
# If it was restricted, allow it again in the global options:
{
    servers {
        protocols h1 h2 h3
    }
}
```
