# HTTP-012: Strict-Transport-Security observed without preload

- **Area:** http
- **Severity:** informational

## What is observed

The Strict-Transport-Security header has no preload directive.

## Why it can matter

The preload directive signals that the site wants to be included in the HSTS preload lists that browsers ship with. A site on those lists is treated as HTTPS-only even on the very first visit, before the browser has seen the header. Without the directive, that first visit is not covered.

## False positives

Preloading is optional and is a long-term commitment. It normally needs a long max-age and includeSubDomains, and getting removed from the lists later is slow. Many well-run sites leave it out on purpose, which is why this is informational. Sentinel only sees the header. It cannot tell whether the site is already on a preload list. It judges this only when max-age is already at least 180 days.

## How to fix

### nginx

```
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
```

### Apache

```
# Needs mod_headers.
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
```

### Caddy

```
header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains; preload');
  next();
});
```
