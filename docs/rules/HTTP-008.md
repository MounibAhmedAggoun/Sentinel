# HTTP-008: Redirect from HTTP to HTTPS not observed

- **Area:** http
- **Severity:** low

## What is observed

A request over plain HTTP was answered without a redirect to HTTPS.

## Why it can matter

A visitor who types a plain http:// address, or follows an old http:// link, reaches the site over an unencrypted connection first. If the server answers there without redirecting to HTTPS, the visitor can stay on plain HTTP. A redirect moves them to HTTPS, and an HSTS header then keeps later visits on HTTPS.

## False positives

Sentinel makes a separate request to the http:// address and follows redirects. The rule applies only when that request got a response and the last response was still plain HTTP. A host that does not answer on port 80 is skipped rather than judged. A service that is meant to be plain HTTP only, such as an internal tool, can match without being a problem.

## How to fix

### nginx

```
server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}
```

### Apache

```
<VirtualHost *:80>
    ServerName example.com
    ServerAlias www.example.com
    Redirect permanent / https://example.com/
</VirtualHost>
```

### Caddy

```
# Caddy redirects HTTP to HTTPS by default for a site with a hostname.
# This makes it explicit:
http://example.com {
    redir https://example.com{uri} permanent
}
```

### Express

```
// Needs app.set('trust proxy', 1) when behind a proxy, so req.secure is correct.
app.use((req, res, next) => {
  if (req.secure) return next();
  res.redirect(301, 'https://example.com' + req.originalUrl);
});
```
