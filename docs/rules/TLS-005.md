# TLS-005: Certificate not trusted by the system certificate store

- **Area:** tls
- **Severity:** medium

## What is observed

The system certificate store did not trust the certificate, and no more specific finding already explains it.

## Why it can matter

The scanning machine could not verify the certificate against its trusted root certificates. A common cause is a server that sends only its own certificate and not the intermediate certificate that links it to a trusted authority. Some clients can fetch the missing piece themselves, and others show an error.

## False positives

The verdict comes from the trust store of the machine that ran the scan, so a different system may reach a different result. A certificate from a private or internal authority is not trusted unless that authority is installed on the scanning machine. Sentinel reports this finding only when no more specific finding, such as expired, self-signed or hostname mismatch, already explains it.

## How to fix

### nginx

```
# Use the file that contains the leaf certificate and the intermediates.
ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
```

### Apache

```
# Use the full chain file as the certificate.
SSLCertificateFile    /etc/letsencrypt/live/example.com/fullchain.pem
SSLCertificateKeyFile /etc/letsencrypt/live/example.com/privkey.pem
```

### Caddy

```
# Caddy sends the full chain for certificates it manages.
# For a manual certificate, put the intermediates in the same file:
tls /path/to/fullchain.pem /path/to/privkey.pem
```
