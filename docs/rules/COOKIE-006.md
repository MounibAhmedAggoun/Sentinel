# COOKIE-006: Cookie observed with a __Host- prefix that breaks its rules

- **Area:** cookie
- **Severity:** low

## What is observed

A cookie named with the __Host- prefix has no Secure flag, no Path=/, or sets a Domain.

## Why it can matter

A cookie whose name starts with __Host- asks for the strictest scope. The browser accepts it only if it has the Secure flag, was set over HTTPS, has Path=/ and has no Domain attribute. That ties the cookie to one exact host. A __Host- cookie that misses one of these rules is rejected by browsers that support prefixes, so it may never be stored.

## False positives

Sentinel judges this only for cookies set on HTTPS responses, and it sees only cookies set on anonymous requests. It records whether Path is exactly / and whether a Domain attribute is present, and it does not store the Path or Domain text. Names are matched case-sensitively, and only at the start of the name. Very old browsers ignore prefixes and may still store the cookie.

## How to fix

### Express

```
// Secure, Path=/ and no domain option.
res.cookie('__Host-sid', value, { secure: true, path: '/' });
// Behind a proxy, also set app.set('trust proxy', 1).
```
