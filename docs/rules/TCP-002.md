# TCP-002: &lt;service&gt; port &lt;port&gt; observed open

- **Area:** tcp
- **Severity:** informational, low, medium

## What is observed

A port for a sensitive service (FTP, Telnet, RDP, MySQL, PostgreSQL, Redis or MongoDB) accepted a TCP connection.

## Why it can matter

FTP, Telnet, RDP and several data stores (MySQL, PostgreSQL, Redis, MongoDB) are services that are usually meant to be reached only from a private network, or that send data without encryption. When one of their ports accepts a connection from the scanning host, it is reachable from there. Sentinel reports reachability only. It does not log in, send commands or check the service.

## False positives

The service may be meant to be reachable from this network, for example a database shared between servers, or a remote desktop behind a VPN that the scan ran from. Sentinel scans from one machine, so the result describes that path only. An open port does not show that the service is misconfigured or has been accessed.

## How to fix

### ufw (Linux firewall)

```
# Allow a trusted address only, then block everyone else.
sudo ufw allow from 203.0.113.10 to any port 5432 proto tcp
sudo ufw deny 5432/tcp
```

### iptables

```
# Accept one trusted address, drop the rest.
sudo iptables -A INPUT -p tcp --dport 3306 -s 203.0.113.10 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 3306 -j DROP
```

### Docker

```
# Bind the published port to localhost only.
docker run -p 127.0.0.1:6379:6379 redis
```

### Redis

```
# redis.conf: listen on localhost only.
bind 127.0.0.1 -::1
```

### PostgreSQL

```
# postgresql.conf: listen on localhost only.
listen_addresses = 'localhost'
```
