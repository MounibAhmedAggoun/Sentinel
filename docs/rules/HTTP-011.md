# HTTP-011: Strict-Transport-Security observed without includeSubDomains

- **Area:** http
- **Severity:** informational

## What is observed

The Strict-Transport-Security header has no includeSubDomains directive.

## Why it can matter

Without includeSubDomains, the Strict-Transport-Security header applies to the host that sent it and not to its subdomains. A browser then treats a subdomain as an ordinary site, so a first visit to it can still start over plain HTTP. Adding the directive extends the HTTPS-only rule to every subdomain.

## False positives

Leaving it out is correct when some subdomains do not work over HTTPS, because browsers would refuse to load them. Adding it is a commitment for the whole max-age, so it should wait until every subdomain, including old or internal ones, serves HTTPS. Sentinel reads one response, and judges this only when max-age is already at least 180 days.

## How to fix

### nginx

```
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

### Apache

```
# Needs mod_headers.
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
```

### Caddy

```
header Strict-Transport-Security "max-age=31536000; includeSubDomains"
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
  next();
});
```
