# COOKIE-004: Cookie observed with SameSite=None but without Secure

- **Area:** cookie
- **Severity:** low

## What is observed

A cookie sets SameSite=None without the Secure flag.

## Why it can matter

A cookie with SameSite=None is sent with cross-site requests, and browsers that enforce the current rules only accept such a cookie when it also has the Secure flag. Without Secure, the browser may reject the cookie, so the feature that depends on it may silently not work.

## False positives

Browsers differ in how strictly they enforce this, and older ones may still store the cookie. Sentinel only sees cookies set on anonymous requests and keeps the first one seen for each name. If the cookie never needs to be sent cross-site, the fix is to change SameSite rather than add Secure.

## How to fix

### nginx

```
# For proxied applications. Needs nginx 1.19.3 or newer.
proxy_cookie_flags ~ secure;
```

### Apache

```
# Needs mod_headers. Appends the flag to every cookie, so it can
# duplicate a flag the application already sets.
Header always edit Set-Cookie ^(.*)$ $1;Secure
```

### Express

```
res.cookie('widget', value, { sameSite: 'none', secure: true });
```
