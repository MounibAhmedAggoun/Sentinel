# TLS-003: Self-signed certificate observed

- **Area:** tls
- **Severity:** medium

## What is observed

The certificate subject and issuer match, so it appears to be self-signed.

## Why it can matter

A self-signed certificate is signed by its own key instead of by a certificate authority. Browsers and other clients have no reason to trust it, so they show a warning, and a visitor cannot tell it apart from a certificate that an attacker substituted.

## False positives

Self-signed certificates are expected on many internal services, development machines and test systems, and on devices that ship with one. Sentinel checks whether the subject and issuer match, so a certificate that is its own issuer by design is reported without being a mistake.

## How to fix

### nginx

```
# Replace the self-signed certificate with one from a trusted authority.
# With certbot, for a public name:
sudo certbot --nginx -d example.com -d www.example.com
```

### Apache

```
sudo certbot --apache -d example.com -d www.example.com
```

### Caddy

```
# Caddy uses a trusted authority by default for public hostnames.
# A self-signed certificate usually means tls internal or a manual
# certificate is configured. Remove it:
example.com {
    # tls internal   <- remove this line
}
```
