# HTTP-014: Content-Security-Policy observed without a base-uri directive

- **Area:** http
- **Severity:** informational

## What is observed

The Content-Security-Policy has no base-uri directive.

## Why it can matter

A &lt;base&gt; tag sets the address that relative links and script paths in a page are resolved against. The base-uri directive limits which addresses it may use. When it is absent, content injected into a page could add a &lt;base&gt; tag that points relative paths to another site, even if the script sources are restricted. The directive has no fallback, so default-src does not cover it.

## False positives

Many sites never use a &lt;base&gt; tag, so the practical effect depends on whether injection is possible in the first place. A site that does use &lt;base&gt; needs a value that matches it, not none. Sentinel reads one response and does not see a policy set through a meta tag.

## How to fix

### nginx

```
# Add the directive to your existing policy. Do not send a second header.
add_header Content-Security-Policy "default-src 'self'; base-uri 'self'" always;
```

### Apache

```
# Needs mod_headers. Add the directive to your existing policy.
Header always set Content-Security-Policy "default-src 'self'; base-uri 'self'"
```

### Caddy

```
header Content-Security-Policy "default-src 'self'; base-uri 'self'"
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Content-Security-Policy', "default-src 'self'; base-uri 'self'");
  next();
});
```
