# TLS-002: Certificate is close to its expiry date

- **Area:** tls
- **Severity:** low, medium, high

## What is observed

The certificate expires within 30 days: low up to 30 days, medium up to 14, high up to 7.

## Why it can matter

A certificate that is close to its expiry date becomes an expired one if it is not renewed in time, and visitors then see browser warnings. A short remaining time is often the first sign that automatic renewal is not working.

## False positives

Some certificate authorities issue short-lived certificates on purpose, and renewal then happens close to the expiry date. A certificate with 25 days left can be normal for a setup that renews at 30 days. Sentinel uses the clock of the scanning machine and reads one certificate from one connection.

## How to fix

### nginx

```
# Check that automatic renewal works:
sudo certbot renew --dry-run
# List certificates and their expiry dates:
sudo certbot certificates
```

### Apache

```
sudo certbot renew --dry-run
sudo certbot certificates
```

### Caddy

```
# Caddy renews automatically. If a certificate is still near expiry,
# look for renewal errors in the logs:
journalctl -u caddy --no-pager | grep -i renew
```
