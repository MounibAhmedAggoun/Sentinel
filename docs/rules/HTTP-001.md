# HTTP-001: Security header not observed: Content-Security-Policy

- **Area:** http
- **Severity:** low

## What is observed

No Content-Security-Policy header was seen in the response.

## Why it can matter

A Content-Security-Policy limits where a page may load scripts and other content from. Without one, the browser applies no such limit, so a script that gets injected into a page runs without restriction. It is one layer of defence against cross-site scripting, not a replacement for fixing the injection itself.

## False positives

Not every site gains much from one. A static site with no user input and no third-party content has less to protect. The header may also be sent only on some responses, or added by a proxy in front of the server. Sentinel reads one response: the last one of the HTTPS request after redirects, or of the plain HTTP request when HTTPS is unreachable.

## How to fix

### nginx

```
# In the server block. Report-only mode logs what would be blocked
# without blocking anything, so start there.
add_header Content-Security-Policy-Report-Only "default-src 'self'" always;
```

### Apache

```
# Needs mod_headers.
Header always set Content-Security-Policy-Report-Only "default-src 'self'"
```

### Caddy

```
header Content-Security-Policy-Report-Only "default-src 'self'"
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Content-Security-Policy-Report-Only', "default-src 'self'");
  next();
});
```
