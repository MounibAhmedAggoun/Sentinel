# HTTP-005: Security header not observed: Referrer-Policy

- **Area:** http
- **Severity:** low

## What is observed

No Referrer-Policy header was seen in the response.

## Why it can matter

When a visitor follows a link, the browser decides how much of the current page address to send to the next site. Addresses can contain identifiers or tokens, so a Referrer-Policy makes that choice explicit.

## False positives

Current browsers already default to a fairly strict policy, so the real risk is smaller than it once was. Setting the header mostly makes the behaviour explicit and consistent across browsers.

## How to fix

### nginx

```
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

### Apache

```
# Needs mod_headers.
Header always set Referrer-Policy "strict-origin-when-cross-origin"
```

### Caddy

```
header Referrer-Policy strict-origin-when-cross-origin
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');
  next();
});
```
