# TLS-008: Certificate observed with a short RSA key

- **Area:** tls
- **Severity:** medium

## What is observed

The certificate has an RSA key shorter than 2048 bits.

## Why it can matter

The strength of an RSA key depends on its length. Keys shorter than 2048 bits are no longer considered strong enough, and certificate authorities and browsers expect at least 2048. A short key makes it cheaper for someone with enough computing power to recover the private key from the public one.

## False positives

Sentinel reads the key of the certificate the server presented first, the leaf, and not the keys further up the chain. A key that is not RSA, such as an ECDSA key, is not judged here, because key sizes are not comparable between types. The server may also present different certificates for different names or addresses, and Sentinel reads one connection.

## How to fix

### nginx

```
# Create a new RSA 2048 key and a certificate request, then install the new certificate.
openssl req -new -newkey rsa:2048 -nodes -keyout example.com.key -out example.com.csr
# Or let certbot issue a new certificate, which uses a strong key by default:
sudo certbot --nginx -d example.com
```

### Apache

```
openssl req -new -newkey rsa:2048 -nodes -keyout example.com.key -out example.com.csr
# Or:
sudo certbot --apache -d example.com
```
