# HTTP-010: Content-Security-Policy observed with weak script sources

- **Area:** http
- **Severity:** low

## What is observed

The script sources in the Content-Security-Policy include unsafe-inline, unsafe-eval or a bare wildcard.

## Why it can matter

A Content-Security-Policy limits where scripts may come from. Sources such as unsafe-inline, unsafe-eval or a bare * widen what the policy allows, so a script injected into a page may still be permitted to run. The policy is then present, but it gives less protection against cross-site scripting.

## False positives

Sentinel reads script-src, or default-src when script-src is absent. It ignores unsafe-inline when a nonce, a hash or strict-dynamic is also present, because browsers ignore it then. A policy set through a meta tag, or one sent only on some responses, is not seen. A site may accept these sources for a time while it moves to nonces or hashes.

## How to fix

### nginx

```
# Static hash of an inline script. Replace the placeholder with the real hash.
# A per-request nonce needs the application to generate it.
add_header Content-Security-Policy "script-src 'self' 'sha256-REPLACE_WITH_HASH'" always;
```

### Apache

```
# Needs mod_headers.
Header always set Content-Security-Policy "script-src 'self' 'sha256-REPLACE_WITH_HASH'"
```

### Caddy

```
header Content-Security-Policy "script-src 'self' 'sha256-REPLACE_WITH_HASH'"
```

### Express

```
import crypto from 'node:crypto';

app.use((req, res, next) => {
  const nonce = crypto.randomBytes(16).toString('base64');
  res.locals.nonce = nonce;
  res.setHeader('Content-Security-Policy', "script-src 'self' 'nonce-" + nonce + "'");
  next();
});
// In a template: <script nonce="...the value of res.locals.nonce...">
```
