# HTTP-004: Security header not observed: X-Frame-Options or CSP frame-ancestors

- **Area:** http
- **Severity:** low

## What is observed

Neither an X-Frame-Options header nor a CSP frame-ancestors directive was seen.

## Why it can matter

If other sites can put a page in a frame, a visitor can be tricked into clicking something the page shows underneath a hidden frame, which is called clickjacking. Either an X-Frame-Options header or a frame-ancestors directive in a Content-Security-Policy limits who may frame the page.

## False positives

Some pages are meant to be embedded, such as widgets or payment forms, and the fix for those is to list the specific sites that may frame them. Sentinel counts either header as protection, so a site with one of them does not get this finding.

## How to fix

### nginx

```
# Allow framing only by the same site.
add_header Content-Security-Policy "frame-ancestors 'self'" always;
# Older browsers read this header instead.
add_header X-Frame-Options "SAMEORIGIN" always;
```

### Apache

```
# Needs mod_headers.
Header always set Content-Security-Policy "frame-ancestors 'self'"
Header always set X-Frame-Options "SAMEORIGIN"
```

### Caddy

```
header Content-Security-Policy "frame-ancestors 'self'"
header X-Frame-Options SAMEORIGIN
```

### Express

```
app.use((req, res, next) => {
  res.setHeader('Content-Security-Policy', "frame-ancestors 'self'");
  res.setHeader('X-Frame-Options', 'SAMEORIGIN');
  next();
});
```
